# WPF и WinForms под .NET 10 (Windows)

В modern-режиме поддерживаются `{$platform WinForms}` и `{$platform WPF}`.
Графические стандартные модули уже содержат эти директивы: для программ
с `uses GraphABC`, `uses FormsABC` или `uses GraphWPF` дополнительных ссылок не требуется.

Платформенные DLL берутся из установленного Windows Desktop Runtime той же
версии .NET (10.0.x); допускается другой номер servicing-патча. Комплект SDK
для выполнения и работы компилятора не требуется.

Консольным программам WindowsDesktop автоматически не подключается.
`{$apptype windows}` выбирает оконную подсистему, но сам по себе не добавляет
графические библиотеки. Реальное подключение платформы, в том числе из
использованного модуля/PCU или явной ссылки, определяет `runtimeconfig.json`.
Для графических программ задаётся STA главного потока, включая консольную
программу, явно использующую WPF.

Системные DLL не копируются в output программы. Core-типы имеют единую
идентичность; WindowsDesktop загружается по необходимости в один постоянный
контекст `PABC.WindowsDesktop`, отдельно от служебных NuGet-зависимостей
компилятора. Например, NuGet сам использует ProtectedData 8, а Desktop 10
может требовать ProtectedData 10: эти версии не подменяют друг друга.
Пользовательские DLL по-прежнему загружаются в выгружаемый контекст;
строгая проверка выгрузки не отключалась.

Конфликтующие явно подключённые DLL не объединяются молча. В частности,
это не механизм автоматической совместимости любых NuGet-пакетов с WPF.
Legacy-режим подключения платформ не изменён. Необязательные зависимости
WPF, отсутствующие в Desktop Runtime (например, отдельный SqlClient), не
включаются в обязательный набор: нужный сторонний провайдер подключается отдельно.
