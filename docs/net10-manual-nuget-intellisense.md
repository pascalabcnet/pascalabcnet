# Восстановление пакетов по запросу IntelliSense

В Windows IDE при выбранном .NET 10 открытие и редактирование `.pas` не разрешают
IntelliSense скачивать недостающие пакеты. Готовые пакеты из общего кеша NuGet
используются автоматически, включая транзитивные зависимости и директивы модулей.

Если пакетов не хватает, в существующей строке состояния появляется кнопка
«Восстановить пакеты». Текст текущего состояния она не заменяет. Кнопка относится
к выбранному редактору; при переключении на legacy, запуске или компиляции скрыта.
При каждом показе состояние читается из актуального редактора, а не из снимка
предыдущего тика таймера. Поэтому после успешной компиляции или явного
восстановления старая кнопка не появляется на мгновение повторно.
Отсутствие пакетов само по себе не является ошибкой LanguageServer.

Нажатие разрешает восстановление только на время одного запроса. Быстрое
восстановление не показывает промежуточный прогресс, но всегда подтверждается
текстом «Пакеты восстановлены». Долгое показывает прогресс после двух секунд
и отмену после пяти. При отмене/ошибке можно повторить действие. Обычная команда
«Завершить» не менялась.

Компиляция и запуск по-прежнему автоматически восстанавливают пакеты. После
успешной компиляции IDE просит IntelliSense обновить ссылки из локального кеша,
не разрешая новое скачивание. Если кеш удалить, действие появляется снова.

## Реализация

IDE передаёт `initializationOptions.manualNuGetRestore=true`. Старые LSP-клиенты,
не передающие эту опцию, сохраняют прежнее автоматическое поведение.
Сервер уведомляет `pascalabc/nugetRestoreRequired` с `uri` и `required`.
Команды `pascalabc/restoreNuGetPackages` и `pascalabc/refreshNuGetPackages` принимают
`{ uri }`: первая разрешает скачивание, вторая только перечитывает локальные пакеты.
Разрешение не сохраняется для последующих правок.

`PackageRestoreRequest.LocalPackagesOnly` ограничивает источники NuGet локальным
каталогом пакетов. Удалённые источники из NuGet.Config не используются в этом
режиме. При нехватке пакетов возвращается отдельный сигнал необходимости restore,
а не успешный неполный граф. Явные конфликты reference/пакетов продолжают проверяться;
строгая проверка выгрузки AssemblyLoadContext не отключалась.

Русские и английские UI-строки находятся в
`bin/Lng/Rus/VisualPascalABCNET_VEC.dat` и `bin/Lng/Eng/VisualPascalABCNET_VEC.dat`.

## Тесты

- `NuGetRestoreTests --manual-intellisense`: пакеты в модулях, отсутствие установки
  при открытии/правках, явное восстановление, подсказки, локальные root/transitive
  пакеты при недоступном удалённом источнике (проверяется отсутствие соединений),
  удаление кеша и подхват восстановления, выполненного компилятором.
- `CompileNet10.Tests --nuget-progress`: кнопка, отложенный прогресс, сообщение
  об успехе, скрытие при смене режима/компиляции; проверка формы LSP-запроса кнопки
  и удаления состояния закрытого редактора.
- `CompileNet10.Tests --manual-nuget <runtime> <NuGetRestoreTests.dll>`: реальные
  процессы, отсутствие автоскачивания, явное восстановление, отмена и повтор в
  том же сервере, автоматическое восстановление компилятором и запуск программы.

Тесты используют временные локальные пакеты, не удаляют пользовательский кеш.
Для ручной проверки закрыть IDE и выполнить `_RebuildNet10Compiler.bat`.

Результат проверки: 477 проверок полного UI/запуска прошли; автономный набор
NuGet (`--runtime-only-child`), модульный LSP и новый сквозной `--manual-nuget`
прошли. Включены неудачное явное восстановление (NU1102), отмена и повтор,
запуск автоматически восстановленной программы и подхват её пакетов сервером.
Modern-комплект и legacy CodeCompletion/net472 собраны успешно.
Работающая IDE не обновлялась: использовался отдельный runtime
`.codex-build/manual-nuget/bin-net10`.

Регрессия повторного появления кнопки проверяется отдельно: сервер снимает
требование восстановления, пока компиляция ещё скрывает кнопку; завершение
компиляции и следующие тики таймера не должны ни разу показать её снова.
Также проверяются окончание ручного восстановления, смена редактора и обратный
случай: если после ошибки компиляции пакетов действительно нет, кнопка возвращается.
