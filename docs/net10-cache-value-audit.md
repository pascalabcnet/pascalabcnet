# Аудит кешей: системный ключ, пользовательская DLL в значении

Проверка выполнена 19 октября 2026 в основном PABC_GIT. После аудита обе
подтверждённые цепочки исправлены. Ниже сохранено описание причин и первоначальных
измерений. Проверка `VerifyPreviousGenerationWasUnloaded` не изменена и не отключена.

Актуальная архитектура второго этапа: [кеши текущего набора DLL](net10-conversion-cache-state.md).
Описанные ниже поля узлов и снимок слабых ссылок относятся к истории исправления;
в современной реализации они уже удалены.

## Подтверждены две дополнительные цепочки удержания

### 1. Кеш преобразований внутри системного семантического узла

`SystemLibrary.integer_type` → `compiled_type_node._explicit_convertions_from`
→ ключ — семантический узел enum из пользовательской DLL → её `Type`.

Запись создаётся настоящим `integer.get_explicit_conversion_from(userEnum)`,
без искусственного помещения чужого объекта под неправильный ключ.
До исправления она оставалась после штатных `ResetDynamicReferenceTypeOperators`
и `CompilerReflectionCacheState.RemoveAssembly`.

Внешний `CompiledTypes` очищается по отражённому типу-ключу. Запись `System.Int32`
сохраняется правильно, но вложенный словарь внутри её значения остаётся загрязнён.
Простая замена всего внешнего состояния также не решает ссылку от статического
`SystemLibrary.integer_type` на тот же семантический узел.

Рядом находятся ещё три кеша того же устройства: `_implicit_convertions_to`,
`_implicit_convertions_from`, `_explicit_convertions_to`. Для них установлена
структурная возможность смешанных ссылок; отдельные реальные сценарии создания
удерживающих записей для каждого из трёх в этом аудите не воспроизводились.

### 2. Общая таблица операторов

`SystemLibrary.ht` → системный ключ `enumgr` / `enumgreq` / `enumsm` / `enumsmeq`
→ `basic_function_node` → параметр пользовательского enum → его `Type`.

Записи создаются обычным `compiled_type_node.get_type_node(userEnumType)`.
Прежний `ResetDynamicReferenceTypeOperators` удалял только `objassign`,
`objeq`, `objnoteq`, поэтому эти четыре записи переживали смену поколения.
У `[Flags]` дополнительно перезаписываются слоты `iand`, `ior`, `ixor`.

## Проверка настоящей выгрузки

Отдельный тест загружает DLL в collectible `AssemblyLoadContext`, создаёт enum
и преобразование через реальные API компилятора, выполняет штатную пару очисток,
вызывает `Unload`, выходит из метода с `NoInlining` и проверяет `WeakReference`
после GC. Первоначальный результат до исправления:

| Состояние | Старый контекст жив |
| --- | --- |
| После штатной очистки | Да |
| После диагностического удаления кеша преобразований integer | Да |
| После удаления также четырёх операторов enum | Нет |

Диагностическое удаление использовалось только для разделения причин.
В окончательном тесте его больше нет: контекст должен выгружаться после
штатной очистки, без ручного удаления удерживающих ссылок из теста.

Исходники сохранены в `tests/ReflectionCacheUnloadTest/SystemValueAudit.cs`
и `tests/ReflectionCacheUnloadFixture/CacheEnum.cs`.

```powershell
dotnet build tests/ReflectionCacheUnloadTest/ReflectionCacheUnloadTest.csproj -p:TargetFramework=net10.0 -p:PABCNET_LEGACY_ONLY=false
dotnet tests/ReflectionCacheUnloadTest/bin/Debug/net10.0/ReflectionCacheUnloadTest.dll --audit-system-values
```

Теперь команда возвращает код 0. Этот сценарий также входит в обычный запуск
`ReflectionCacheUnloadTest` без флага, а не остаётся необязательным аудитом.
Первый вариант теста на прежнем `TreeConverter.dll` падал с сообщением
«A conversion cache still retains the user key or value» (отрицательный контроль
исходной утечки). После переноса кешей текущий тест дополнительно проверяет
владение: реализация с полями узла отклоняется с сообщением
«A conversion dictionary is still stored on a compiled type node».

## Что изменено

- В первом исправлении словари внутри узлов очищались по принадлежности ключей
  и значений старой DLL; исходные узлы обнаруживались через слабый снимок.
- Вторым этапом все четыре словаря перенесены в состояние текущего набора DLL.
  Теперь они заменяются целиком при его перезагрузке, без обхода системных узлов.
  Самим постоянным узлам нечем удерживать старые словари.
- Внутри неизменного набора DLL кеши переиспользуются. При его смене чисто
  системные записи этих четырёх кешей также вычисляются заново по необходимости.
- В первом исправлении таблица операторов восстанавливалась из снимка.
  Следующим этапом она разделена на постоянную базу и слой текущего поколения:
  теперь база не перезаписывается, а временный слой очищается целиком.
  Подробности: [таблицы операторов по поколениям](net10-operator-generations.md).
- Эти изменения включены только для `PABCNET_MODERN`; legacy-сборка проверена.

Текущие тесты проверяют реальное enum → integer, оба вида enum, все четыре
словаря, владение состоянием и полное освобождение старых кешей без удержания
их постоянным узлом, а также неявные/явные преобразования пользовательской DLL.
`WeakReference` проверяется после выхода из `NoInlining`-метода.

В `CompilerAssemblyReloadTest` добавлены настоящие компиляции с enum/Flags:
неизменные DLL переиспользуются, затем четыре раза выполняется rebuild в одном
процессе. Полученные программы запускаются и проверяют преобразования,
сравнения enum, операции с Flags и обычный целочисленный `and`.

## Результаты проверки исправления

- `ReflectionCacheUnloadTest` — успешно, включая оба удержания, Flags,
  выборочную очистку, полный сброс и реальный GC/`WeakReference`.
- Отрицательный контроль со старым `TreeConverter.dll` — ожидаемое падение.
- `CompilerAssemblyReloadTest --stress` — успешно: четыре rebuild с enum/Flags,
  все прежние сценарии ссылок/PCU и 50 замен DLL в одном процессе;
  private memory 134 → 129 МБ.
- LSP `--nuget-progress` — успешно: локальные пакеты, extension-методы,
  повторные восстановления, отмена и ожидание без ложного таймаута.
- LSP `--nuget-cache-removal-ml` — успешно: пять восстановлений ML.NET/MKL
  без перезапуска LanguageServer.
- Полный штатный набор .NET 10 — 1913 пройдено, 0 ошибок, 44 пропущено
  (41 modern-исключение); список исключений в этой работе не менялся.
- Сборки modern runtime и legacy TreeConverter/net472 — успешно.

Для тестов использовались отдельные каталоги `.codex-build`, рабочие DLL IDE
не подменялись. Исходники новых тестов входят в Git; логи/бинарники — нет.

## Что проверено кроме найденных ошибок

| Группа | Результат и граница проверки |
| --- | --- |
| `Members`, handle-кеши, `EntryTypes`, `MemberCache` | Прямой тест прежнего исправления проходит; учитываются значения и `ReflectedType`, а не только ключ. |
| `ExtensionMethods`, `TypeExtensions`, `GenericArrayTypeExtensions`, `GenericParameterTypeExtensions` | Расширенный прямой тест: методы пользовательской DLL под системными/числовыми ключами удаляются. Независимая системная запись сохраняется. |
| `ArraysWithExtensionMethods`, `GenericsWithExtensionMethods` | Тест пользовательского типа в значении проходит. |
| `Namespaces`, `Types`, `CompiledPascalTypes`, `SpecialTypes`, ключи `Members` | Тест `List<UserType>` проходит: принадлежности внешнего типа системной сборке недостаточно, проверяются аргументы generic-типа. |
| `NamespaceTypes` | Полностью очищается при удалении сборки; смешанное содержимое не сохраняется. Проверено по коду. |
| `TypeSearch`, `CachedTypeExtensions` | По коду проверяются отражённые типы в значениях/элементах. Отдельного нового прямого теста здесь нет. |
| `TypeHandles` | По коду заполняется исключительно из `assembly.GetTypes()` под ключом той же сборки. Произвольные типы чужой DLL туда штатно не добавляются. |
| `PropertyNodes`, `FieldNodes`, `ConstructorNodes`, `CompiledMethods`, `CompiledConstructors` | При создании оболочка соответствует ключу; проверка ключа учитывает сигнатуру, generic-аргументы и `ReflectedType`. Это не доказательство отсутствия произвольных более глубоких семантических связей. |
| `Assemblies`, `AssemblyNamespaces`, `CurrentUsedAssemblies`, `AssembliesByName`, `AssemblyFileDates`, `AssemblyFullPaths` | Ссылки на сборки удаляются непосредственно. Значения namespace/path/date не содержат `Type`/`MemberInfo`. Проверено по коду. |
| `StandardTypes` | Заполняется только встроенными числовыми типами, `bool`, `char`. Пользовательские типы не добавляются. |
| `CodeCompletion.TypeTable`, `TypeScope.instance_cache` | Полная очистка при очередном анализе, включая extension-методы стандартных scope. Порядок очистки относительно смены поколения стоит покрыть отдельным адресным тестом; он не равнозначен фильтрации по ключу. |
| Кеши документации и PCU IntelliSense | Есть очистка поколения; в `ParserTools.AssemblyDocCache` значение `XmlDoc` хранит строки/индексы, а не отражённые типы. Проверено по коду. |
| `generic_convertions` | Коллекции инстанцирований очищаются в `syntax_tree_visitor.internal_reset()`. Точное время жизни вне обычного compiler reset требует отдельного сценария. |
| Пути системных ссылок, кеш identity/fingerprint | Хранят пути, имена, версии, даты, хеши, не экземпляры `Assembly`/`Type`. |

Отдельные долгоживущие объекты вроде `compiled_namespace_node.compiled_namespaces`
и сохранённых таблиц символов требуют проверки времени жизни полного дерева;
данный аудит не объявляет их доказанно безопасными или доказанными утечками.

## Граница результата

Обе подтверждённые цепочки исправлены и закреплены обязательными тестами.
Это не доказательство отсутствия любых возможных удержаний полного семантического
дерева: указанные выше ограничения аудита остаются актуальными.
