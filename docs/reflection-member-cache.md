# Кеш членов .NET-типов

Кеш `NetHelper.GetMembers` хранит методы, свойства, поля, события и конструкторы
отражённых .NET-типов, а также известные методы расширения для этих типов.
Это не кеш семантических деревьев Pascal-модулей из PCU.

Таблица типа строится при первом обращении. Она содержит всех известных
кандидатов независимо от набора ссылок текущей компиляции. Новая впервые
загруженная DLL дополняет уже существующие таблицы на месте, в том числе для
системных типов, которые она расширяет через интерфейсы или базовые классы.

При поиске методы расширения фильтруются по сборке, в которой объявлены:
`MethodInfo.DeclaringType.Assembly`. Отключённая DLL не участвует в выборе,
но её кандидаты остаются в полном кеше. Отдельно учитывается режим
`UsePABCRtl`: при работе через PCU методы RTL не должны участвовать в поиске.
Обычные унаследованные члены из транзитивных зависимостей не отсекаются как
неподключённые методы расширения.

Повторная компиляция и повторное подключение неизменной DLL не очищают и не
заменяют таблицы метаданных. Если все кандидаты доступны, поиск возвращает
существующий список без создания отфильтрованной копии.

При смене выгружаемого набора DLL под .NET 10 удаляются удерживающие его ссылки.
Если несколько сборок расширяют один системный тип, очистка общего индекса
удаляет только методы выгружаемой сборки, сохраняя методы остальных.
Проверка освобождения `AssemblyLoadContext` остаётся включённой.

## Проверки

- `tests/LegacyTestRunnerTests/Test-PABCRtlOperators.ps1`: холодная компиляция
  через RTL без системных PCU, обычная компиляция через PCU, запуск результатов;
  четыре перехода RTL → PCU → RTL в одном компиляторе с проверкой сохранения
  объекта таблицы и скрытия операторов отключённой RTL.
- `tests/ReflectionCacheUnloadTest/ExtensionMemberCacheTests.cs`: позднее
  подключение DLL, включение/отключение extension-методов, интерфейсы и массивы,
  сохранение таблиц и списков при неизменных ссылках, отсутствие накопления
  дубликатов при запросах IntelliSense, сохранение методов другой DLL в общем
  индексе и освобождение выгружаемого контекста.
- Новый тест полного кеша входит в обычный `ReflectionCacheUnloadTest`, вместе
  с существующими проверками операторов, преобразований, enum и Flags.

Полный x86-прогон не включается.

Кеш поиска типов — отдельный от кеша членов. В нём сохраняются найденные
типы и промахи для текущего индекса DLL. При индексировании новой DLL
удаляются только отрицательные записи: старое «тип не найден» не должно скрыть
тип из DLL, подключённой позднее в той же компиляции. Положительный кеш
и таблицы членов не очищаются; повторное подключение известной DLL не
сбрасывает промахи. Прямое добавление типа адресно отменяет промах его имени.
Проверки: `tests/TypeLookupCacheTests` и `tests/MessageBoxLookupTests`.
