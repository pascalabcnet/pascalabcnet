# Таблицы операторов: постоянная база и текущее поколение

В modern-компиляторе больше нет одной изменяемой таблицы с последующим
восстановлением из снимка. В `SystemLibrary` разделены два слоя:

- `permanentOperators` — операторы, зарегистрированные при начальной
  инициализации системной библиотеки;
- `generationOperators` — все регистрации после завершения этой инициализации.

Обе группы по-прежнему проходят через общий `add_stand_type`.
Самим реализациям enum, Flags и других операторов ничего знать о таблицах не надо.
Постоянная база после инициализации этим методом больше не изменяется.

`find_operator` сначала ищет запись поколения, затем постоянную. Последняя
регистрация в текущем поколении имеет приоритет, как и раньше в общей таблице.
При отсутствии ключа в обеих таблицах остаётся прежний `KeyNotFoundException`.

При смене поколения `ResetDynamicReferenceTypeOperators` полностью очищает
`generationOperators`. Копирования/восстановления базы, списка специальных ключей,
проверки атрибута Flags или сигнатур операторов для этой очистки нет.
Удаление временной записи автоматически открывает прежнюю постоянную запись.

Жизненный цикл определяется местом регистрации: инициализация системы либо
текущее поколение. Он не определяется тем, из системной или пользовательской
DLL пришёл тип. Будущие постоянные регистрации, если они понадобятся после
инициализации, должны получить явно заданный постоянный срок жизни, а не
автоматическое исключение из очистки по имени оператора.

Изменение ограничено `PABCNET_MODERN`. Legacy использует прежнюю таблицу `ht`.
Алгоритмы создания enum/Flags, кеши преобразований из предыдущего этапа и
`VerifyPreviousGenerationWasUnloaded` этим этапом не меняются.

Следующий отдельный этап — [перенос кешей преобразований](net10-conversion-cache-state.md)
в состояние текущего набора DLL; две таблицы операторов при этом сохраняются.

## Тесты

Новый `OperatorGenerationTests` включён в обычный `ReflectionCacheUnloadTest`.
Отдельный запуск:

```powershell
dotnet build tests/ReflectionCacheUnloadTest/ReflectionCacheUnloadTest.csproj -p:TargetFramework=net10.0 -p:PABCNET_LEGACY_ONLY=false
dotnet tests/ReflectionCacheUnloadTest/bin/Debug/net10.0/ReflectionCacheUnloadTest.dll --operator-generations
```

Он проверяет через общий путь регистрации, без вызова реализации enum/Flags:

- временное перекрытие постоянного оператора и приоритет последней регистрации;
- поиск другого оператора в постоянной базе;
- временный ключ, которого вообще нет в постоянной базе;
- неизменность объекта постоянной таблицы и всех её записей;
- три смены поколения, исчезновение временного ключа и возврат базового оператора;
- сохранение ошибки при поиске отсутствующего ключа;
- настоящую выгрузку DLL с пользовательским типом в значении оператора,
  проверенную через `WeakReference` после `Unload` и GC вне `NoInlining`-метода.

Тесты прежних удержаний enum/Flags дополнительно проверяют пустоту слоя поколения
и поиск всех постоянных операторов после очистки. `CompilerAssemblyReloadTest`
проверяет реальные компиляции и запуск enum/Flags после четырёх rebuild в одном
процессе, все шесть сравнений enum (`<`, `>`, `=`, `<>`, `<=`, `>=`),
переиспользование неизменных DLL и нагрузку с 50 заменами DLL.

## Результаты проверки этого этапа

- Прямые тесты двух слоёв, прежние тесты кешей и реальная выгрузка — успешно.
- Все шесть сравнений enum и операции Flags после четырёх rebuild — успешно.
- Стресс-прогон: 50 замен DLL в одном процессе, private memory 130 → 126 МБ.
- Пять восстановлений ML.NET/MKL в одном LanguageServer — успешно.
- Полный штатный прогон .NET 10: 1913 успешно, 0 ошибок, 44 штатных пропуска
  (41 modern-исключение); список исключений не менялся.
- Сборки modern-комплекта и legacy TreeConverter/net472 — успешно.

Проверка выгрузки осталась включённой. Рабочие DLL IDE не подменялись:
сборка и прогоны выполнялись на отдельных комплектах в `.codex-build`.
