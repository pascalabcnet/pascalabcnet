# Уведомления о документах старой IDE

Необязательный `IWorkbenchDocumentEvents` реализован тем же `Form1`, который
предоставляет `IWorkbenchDocumentService`. Исторический интерфейс не расширяется;
старые плагины не обязаны подписываться и продолжают работать как раньше.

```csharp
var events = workbench.ServiceContainer.DocumentService as IWorkbenchDocumentEvents;
if (events != null)
{
    events.DocumentOpened += OnOpened;
    events.DocumentClosed += OnClosed;
    events.DocumentRenamed += OnRenamed;
    foreach (var document in events.GetOpenDocuments()) Attach(document);
}
```

Подписка и получение снимка выполняются синхронно на потоке IDE. При отключении
плагина нужно отписаться от событий и от обработчиков текста редакторов.

- `GetOpenDocuments()` возвращает новый массив из существующего `OpenDocuments`,
  включая неактивные, плавающие и metadata-вкладки. Второго реестра нет.
- `DocumentOpened` отправляется один раз для новой вкладки после загрузки текста
  и инициализации. Выбор уже открытой вкладки не вызывает событие. Новая программа
  получает его с назначенным IDE именем, даже если ещё не сохранена на диск.
- `DocumentClosed` отправляется после подтверждения закрытия и удаления из
  `OpenDocuments`, но **до** уничтожения редактора: можно снять обработчики текста.
  Отмена закрытия события не создаёт. Это уведомление, не запрос разрешения закрыть.
- `DocumentRenamed` отправляется после успешного `Save As` с изменением имени,
  а также при замене пустой новой вкладки открываемым файлом. В последнем случае
  текст нового файла уже загружен. Обычное сохранение под прежним именем его не создаёт.
- В `WorkbenchDocumentEventArgs` имена зафиксированы в момент события: `FileName`
  и (для переименования) `PreviousFileName`. Сам документ может позже поменяться;
  текст для асинхронного запроса нужно копировать сразу, на потоке IDE.
- Изменения текста, Undo/Redo и перезагрузка файла остаются существующим событием
  `document.TextEditor.Document.DocumentChanged`; оно не дублируется в контракте.

Для LSP переименование означает `didClose` старого URI и `didOpen` нового с текущим
текстом. Metadata и не-Pascal документы фильтруются потребителем, а не оболочкой.
Ошибки подписчиков диагностируются через `Trace` и не прерывают завершённые
операции IDE или уведомление остальных подписчиков. Обработчики не должны блокировать
поток IDE или синхронно запускать другие операции открытия/закрытия.

CompileNet10Plugin использует эти события для синхронизации с LanguageServer.
`Net10LanguageDocuments` подписывается на текст только в активном режиме .NET 10
при включённом пользовательском IntelliSense. Полные тексты копируются на потоке IDE;
передача идёт в фоне, после 200 мс без изменений. Очередь объединяет накопившиеся
снимки, версии каждого URI растут; неизменённый текст повторно не отправляется.
Metadata и другие языки не входят в фоновую синхронизацию исходников.
Дисковые исходники не перезаписываются.

При возврате на net472 отправляется `didClose`, обработчики текста снимаются.
Сервер остаётся жив; возврат на .NET 10 передаёт актуальные открытые документы заново.
При потере связи ошибка видна в отдельном временном поле статуса. Следующее действие
редактора восстанавливает соединение и полный снимок, без бесконечного цикла рестартов.
`LSP: N файлов` означает число переданных открытых документов, не подтверждение
завершения их семантического анализа: стандартные LSP-уведомления не имеют ответа.
Изменение текста не добавляет бегущих сообщений компилятора или статуса.

Закрытие IDE снимает все подписки, отправляет `shutdown`/`exit`; если завершение
задерживается, через 2 секунды собственный процесс сервера принудительно завершается.
`ApplicationExit` также завершает оставшийся процесс, если приложение выходит раньше
завершения асинхронного shutdown.
Для completion после точки сначала отправляется актуальный снимок всех редакторов,
затем запрос `textDocument/completion`. Передача снимков и запрос сериализованы,
старый ожидающий снимок не может откатить более свежий. Отмена подсказки не убивает
общий сервер; поздние ответы не вставляются после правки выражения/другого модуля,
смены позиции, Escape, потери фокуса, Save As, закрытия и переключения платформы.
Разрешено допечатывание идентификатора после точки: штатное окно заменяет префикс.
Обработчики клавиатуры отсоединяются при возврате на net472, чтобы не менять результат
исторического multicast-обработчика редактора. Штатное окно принимает готовые данные
без обращения к старым семантическим кэшам.
Hover использует ту же очередь снимков и `textDocument/hover`, но запускается существующим
`TextArea.ToolTipRequest`. Плагин передаёт готовое описание в `TooltipServiceManager.ShowExternalHint`;
штатное окно и исторический путь net472 общие, второго окна/анализатора в IDE нет.
Плагин подписывается только в режиме .NET 10 при включённой подсказке наведения.
Устаревшие ответы отменяются при движении мыши за пределы идентификатора, правке любого
открытого модуля, вводе клавиши, прокрутке, потере фокуса, Save As, закрытии и смене платформы.
Запрос не перекрывает уже выбранные подсказки маркеров/свёрток/отладчика.
Для наведения внутри metadata-вкладки её текст отправляется только по запросу,
с виртуальным URI `pascalabc-metadata-view:`. Он не подменяет исходный модуль,
не участвует в счётчике исходных файлов и закрывается следующим обычным снимком.
Completion, signature и навигация из metadata-вкладки этим шагом не подключаются.
Адаптация сгенерированного текста к Pascal-парсеру выполняется только в серверной
копии для анализа, без изменения содержимого вкладки или записи файла.
Signature использует ту же очередь и `textDocument/signatureHelp` после `(`, `[` и `,`.
Для готовых описаний/диапазонов параметров в штатном окне есть необязательный
`IExternalInsightDataProvider`, без изменения исторического `IInsightDataProvider`.
Старый провайдер и его отрисовка сохранены; внешний путь не обращается к старым DOM-кэшам.
Плагин наблюдает `DocumentChanged` и запускает запрос после обычной вставки/перемещения
каретки: второй boolean-обработчик клавиш не перезаписывает результат completion.
Вложенные вызовы используют стек окна, запятая заменяет текущий провайдер без роста стека.
Потеря фокуса проверяется после завершения UI-события: штатное окно при показе
кратковременно переводит фокус с TextArea на контейнер редактора и обратно.
Сквозной тест `CompileNet10.Tests.exe --signature-ui <bin-net10>` проверяет настоящую
вставку `(`, обновление по запятой, закрытие по `)` и уход из редактора, включая живой LSP.
При открытии списка completion окно параметров закрывается: одновременно два
обработчика стрелок/Enter/Tab не конкурируют. Настройка параметров управляется отдельно.
Компиляция/запуск работают через прежний Controller, настройки IntelliSense не изменяются.

Ctrl+щелчок использует ту же очередь снимков и стандартные запросы LSP
`textDocument/implementation` / `textDocument/definition`. Сервер вызывает существующие
DOM-методы; плагин переводит UTF-16 координаты в однобазовые координаты IDE один раз.
Результат применяется на UI-потоке через `ExecuteSourceLocationAction`, с проверкой
актуальности текста, каретки, фокуса и режима. Для CLR сервер возвращает виртуальный
URI и по запросу `pascalabc/metadata` — текст/заголовок штатной вкладки метаданных.
Сервер хранит не более 32 таких документов; источники/пользовательские файлы не записываются.
Подчёркивание при Ctrl-наведении принадлежит только этому обработчику: маркеры ошибок,
точек останова и других плагинов не удаляются. Контракт оболочки расширять не требуется.
