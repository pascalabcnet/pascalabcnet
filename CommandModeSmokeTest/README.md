# Проверка commandmode

Оба консольных компилятора поддерживают `commandmode` на `net472` и `net10.0`.
В этом режиме компилятор остаётся в памяти и принимает команды старой оболочки
через stdin/stdout. Реализация общая: `pabcnetc/CommandConsoleCompiler.cs`;
проект `pabcnetcclear` подключает её как linked source.

После сборки обоих компиляторов для соответствующей платформы:

```powershell
dotnet run --project CommandModeSmokeTest/CommandModeSmokeTest.csproj -- bin/pabcnetc.exe bin/pabcnetcclear.exe
dotnet run --project CommandModeSmokeTest/CommandModeSmokeTest.csproj -- bin-net10/pabcnetc.dll bin-net10/pabcnetcclear.dll
```

Сам проверяющий клиент работает на .NET 10, а запускаемые компиляторы — на своих
платформах. Проверка legacy EXE этими командами предназначена для Windows.

Тест запускает каждый компилятор один раз и выполняет три компиляции: успешную,
с ошибкой и снова успешную после изменения текста. Исходник отсутствует на диске:
клиент передаёт несохранённый текст через callback протокола. Проверяются Unicode
в пути и тексте, передача настроек и стандартного модуля, сообщения об ошибках,
обновление выходной сборки, сохранение процесса, запрос рабочего набора памяти,
сборка мусора и штатный выход. Артефакты создаются в отдельном временном каталоге
и удаляются после проверки. Компиляция и обмен сообщениями проверяются без GUI;
запуск полученных программ и реальная работа Mono в этот тест не входят.

## Формат канала

- stdin и stdout используют UTF-8;
- клиент посылает строку с трёхзначным кодом команды и необязательным аргументом;
- для имени файла, каталога вывода и ответа с текстом исходника аргументом служит
  длина строки в UTF-16 code units (`string.Length`); за строкой команды идут
  ровно столько символов без дополнительного перевода строки;
- сообщения компилятора заканчиваются `ConsoleCompilerConstants.DataSeparator`
  (`]` + CRLF + `[`), а не просто переводом строки;
- во время компиляции клиент отвечает на запросы существования файла, времени
  изменения и актуального текста; после `CompilationFinished` ожидает `Ready`;
- номера команд и разделитель составных аргументов определены в
  `Compiler/ConsoleCompilerCommands.cs` (для Unix разделитель аргументов иной).

Поиск разделителя в `Tools.SplitString` использует `StringComparison.Ordinal`:
лингвистический поиск управляющих символов под .NET 10 неверно разбирал команду
добавления стандартного модуля и приводил к `FormatException`. Проверка выше
воспроизводит этот случай через команды настройки локали и стандартных модулей.
Ошибка чтения команды теперь выводится в stderr с кодом завершения 1 вместо
необработанного исключения.

`BinaryFormatter` из этого канала удалён: прежняя отправка целых объектов
`CompilerOptions`/`CompilerInternalDebug` давно была отключена в `RemoteCompiler`.
Действующие настройки передаются отдельными командами. Зарезервированные коды
221/222 не используются для передачи объектов.

Это существующий протокол оболочки, не LSP и не JSON-протокол
`PABCCompilerController`. Возвращение `commandmode` само по себе не переключает
IDE на .NET 10 и не добавляет современный отладчик.
