# Встроенные ресурсы .NET 10

```powershell
dotnet run --project tests/ManagedResourceTests/ManagedResourceTests.csproj -c Release -- D:\PABC_GIT
```

Нужны подготовленные `bin` и `bin-net10` со стандартными PCU. Тест использует
штатные консольные компиляторы, исходные тесты не изменяет, создаёт файлы во
временной папке с пробелами и кириллицей.

Для Framework (контроль без изменений) и .NET 10 проверяются:

- компиляция и запуск исходного `uses_in3_derectives.pas`, включая `1.txt`
  из подключённого модуля;
- несколько ресурсов в одном EXE, бинарные данные, пустой ресурс,
  имена и содержимое с кириллицей;
- ресурсы в DLL и их чтение из запущенной программы;
- программа без собственных ресурсов.

Проверяются и фактическое чтение при запуске, и записи ManifestResource,
длины и байты в PE. Исходники Framework-генератора не меняются.

Причина исходного сбоя: modern-ветка не вызывала `DefineManifestResource`,
которого нет у нового генератора, и не передавала альтернативный блок ресурсов
в `ManagedPEBuilder`. Теперь создаются manifest-записи и блок данных с длиной
перед каждым ресурсом. Framework продолжает использовать прежний механизм.

В полном modern-прогоне `CrossTargetTestRunner` дополнительно запускает
`uses_in3_derectives`, чтобы исчезновение ресурса снова обнаруживалось в CI.
