# Compile .NET 10: экспериментальный плагин

Отдельный плагин `net472` для существующей IDE. Добавляет флажок **.NET 10**
в стандартное меню **Программа**. Через JSON Lines обращается
к долгоживущему контроллеру из текущего PascalABC.NET и компилирует текущий текст редактора.
Запрос выполняется асинхронно; результаты и диагностика идут в сообщения
компилятора. При закрытии IDE плагин завершает свой контроллер.

Выбор платформы действует для всех вкладок только до закрытия IDE и не сохраняется
в настройках. По умолчанию запускается обычный режим .NET 4.7.2. Общие команды
Compile, Run и Stop направляются плагину только при установленном флажке.
«Перекомпилировать» использует тот же Compile с `rebuild=true` и пересобирает
модули из исходников. События компилятора и стандартная панель ввода не меняются.
В .NET 10 старый IntelliSense (оба варианта), старый отладчик и настройка ускорения
PABCRtl временно недоступны; сохранённые пользовательские настройки не изменяются.
При возврате к .NET 4.7.2 анализ открытых документов возобновляется.
Переключение во время компиляции, выполнения или отладки запрещено.
При переключении статус показывает только имя платформы. Как в старом режиме,
обычный запуск/ввод/завершение не заменяют результат компиляции в статусной строке;
сообщения об ошибках сохраняются. Подробные события остаются в журнале компилятора.
Новая версия плагина требует пересборки IDE и `PluginsSupport.dll`.
В оболочке без стандартного меню остаются отдельные Compile10/Run10/Stop10.

## Сборка

Из корня основного репозитория:

```powershell
& .\scripts\build-compile-net10-plugin.ps1 -Configuration Debug
```

Предварительно должна быть собрана обычная IDE: проект использует существующий
`bin/PluginsSupport.dll` как контракт и не пересобирает проекты оболочки.
Если плагин уже загружен в IDE, перед пересборкой закройте эту IDE.

Для стандартной панели ввода нужна IDE и `PluginsSupport.dll` из текущих исходников:
`dotnet build VisualPascalABCNET/VisualPascalABCNET.csproj -c Release -p:PABCNET_LEGACY_ONLY=true`.
В старой бинарной оболочке без нового необязательного интерфейса Run10 сообщает
о необходимости пересборки; скрытого перехвата обработчиков и новой панели нет.

Результат — `bin/CompileNet10Plugin.dll` и единый полный `bin-net10/`.
Controller и Worker собираются только из проектов текущего репозитория;
их зависимости .NET 10 изолированы от DLL оболочки net472.
Скрипт вызывает `scripts/build-net10-runtime.ps1`. Оба консольных компилятора,
Controller и Worker собираются вместе через `Net10Runtime.slnx`, с общими DLL.
Плагин запускает Controller непосредственно из `bin-net10`, без второй копии.
`Lib` и `Lng` комплектуются версионируемыми файлами текущего `bin` без
старых PCU, DLL, EXE и PDB. Модули компилируются из исходников при необходимости.
Проект не добавляется в `PascalABCNET.sln`; основная сборка и установщик
не меняются и не требуют .NET 10 SDK. Для отдельной сборки host нужен .NET 10 SDK;
для запуска готового комплекта — установленный .NET 10 runtime.

Сборка только плагина (например, из Visual Studio) остаётся обычной:
`dotnet build VisualPlugins/CompileNet10/CompileNet10.csproj -c Debug`.
Она не пересобирает host автоматически. Если его ещё нет, сначала выполните скрипт выше.

## Проверка в IDE

1. Запустить `bin/PascalABCNET.exe` после сборки плагина.
2. В меню **Программа** установить флажок **.NET 10**.
3. Открыть или создать `.pas` и использовать обычные кнопки компиляции/запуска;
   сохранять изменения не требуется. Проверить также «Перекомпилировать»,
   запуск по F9, стандартную остановку, возврат к старому режиму и сброс флажка
   после перезапуска IDE. Настройки IntelliSense и ускорения должны сохраниться.
   В сообщениях компилятора должен появиться результат или диагностика.
   Ошибки также выводятся в стандартный список IDE: двойной щелчок или Enter
   переводит к указанному файлу, строке и столбцу. Перед новым запросом список
   очищается. Новые вкладки должны иметь назначенное полное имя исходника
   (обычная новая программа IDE уже получает такое имя).
   Предупреждения также попадают в стандартный список с жёлтым значком и переходом
   к исходной строке. Compile открывает список предупреждений; Run заполняет его,
   но не переключает окно, как в обычной IDE. Предупреждения не мешают запуску.
   Оба запроса, Compile и Run, содержат `runtimeModule=__RedirectIOMode` и
   `sourceFiles`: главную программу и открытые изменённые Pascal-исходники.
   Новые открытые `.pas`, ещё не существующие на диске, включаются также при
   отсутствии отметки изменения. Неизменённые сохранённые модули читаются с диска.
   Снимок собирается до отправки запроса, включая скрытые и плавающие вкладки;
   текст не переписывается и исходники на диск не записываются.
   Выходные файлы создаются в `net10-output` рядом с исходником.
   **Run10** сначала компилирует файл и только при успехе запускает
   сборку через `DotnetPath` без внешней консоли. Для запуска запрос содержит
   `runtimeModule=__RedirectIOMode`; программа получает `[REDIRECTIOMODE]` и handshake `GO`.
   Вывод, включая текст без перевода строки и исключения, идёт в окно вывода
   исходной вкладки IDE. Успешный код завершения не печатается.
   Сам запуск не переключает на окно вывода: оно открывается при выводе или запросе ввода.
   По `[READLNSIGNAL]` от `Readln` открывается стандартная панель ввода IDE.
   Enter и кнопка ввода отправляют текст в процесс Run10, после чего панель скрывается.
   Стандартная кнопка остановки на этой панели останавливает Run10;
   общая кнопка остановки на toolbar доступна также вне ожидания ввода.
   Ожидание и набранный текст привязаны к исходной вкладке обычным механизмом IDE.
   После завершения/остановки Run10 обработчик освобождается. Обычный запуск net472
   использует прежний RunManager без изменения протокола или обработки ввода.
   Рабочий каталог — каталог исходника; аргументы берутся из настроек запуска IDE.
   Процесс по-прежнему принадлежит плагину и запускается без старого отладчика.
   Жизненный цикл подключён к общему RunManager: `Starting`/`Exited`,
   `ProcessStarting`/`ProcessExited`, `IsRun`, отметка запуска вкладки,
   обычные Stop/KillAll и восстановление кнопок. Вывод и исключения идут
   через штатные обработчики IDE; исключение с координатами попадает в список
   ошибок с переходом к исходнику, если стек содержит файл и строку.
   `BeforeCompile` вызывается до снимка редакторов,
   `ChangeArgsBeforeRun` — до запуска процесса. События не дублируются.
   Одновременно допускается одна программа .NET 10; обычный запуск IDE
   останавливает экспериментальную программу. Закрытие её вкладки или IDE
   также завершает процесс. Переключение вкладки не перенаправляет вывод.
   В статусной строке отображаются подготовка, компиляция, результат компиляции,
   выполнение, ожидание ввода, остановка и завершение .NET 10. Плагин запрашивает
   `emitEvents=true`: реальные фазы Worker передаются через Controller до итогового
   ответа. В сообщениях отображаются чтение DLL/PCU, преобразования, interface/
   implementation, сохранение PCU, завершение и время. Статус использует привычные
   тексты IDE с префиксом `.NET 10:`, реальным числом строк, ошибок и предупреждений.
   Событие Ready при перезагрузке не считается успешной компиляцией; при повторе
   запроса после сбоя Worker фазы могут повториться. Старые клиенты без emitEvents
   продолжают получать ровно один итоговый ответ. Старое ядро IDE не подменяется.
   Если обычная IDE обновила статус, позднее сообщение .NET 10 его не перезаписывает.
4. Проверить обычную компиляцию существующей кнопкой IDE.
5. Получить красную строку обычной компиляцией, затем успешно выполнить Run10:
   старая подсветка должна исчезнуть. Проверить обычный Stop, KillAll, переключение
   и закрытие вкладки, повторный Readln, runtime-ошибку с переходом к строке,
   а затем обычный запуск net472. Ручные проверки выполняются в пересобранной IDE.

Чтобы отключить эксперимент, закройте IDE, уберите `CompileNet10Plugin.dll`
из каталога приложения и запустите IDE снова. При использовании другой копии
IDE копируются DLL плагина, исходный INI и соседний каталог `bin-net10`,
без замены её `PluginsSupport.dll` или других DLL оболочки. Можно собрать
плагин непосредственно туда (runtime остаётся в `bin-net10` текущего репозитория;
для другой IDE укажите его абсолютный путь в INI):

```powershell
& .\scripts\build-compile-net10-plugin.ps1 -IdeDirectory 'D:\Other IDE' -Configuration Release
```

Старая копия `bin/CompilerHost/net10` больше не используется при новых настройках,
но автоматически не удаляется. Скрипты установщика пока не изменяются.

При первой сборке настройки копируются в `bin/CompileNet10Plugin.ini`;
существующий пользовательский INI не перезаписывается. `RuntimeDirectory` указывает
на полный готовый runtime с `PABCCompilerController.dll`, `PABCCompilerWorker.dll`,
их `.runtimeconfig.json`/`.deps.json`, DLL зависимостей и стандартными модулями.
По умолчанию: `RuntimeDirectory=..\bin-net10`. Такой же локальный путь
используется без INI. Он вычисляется относительно `AppDomain.CurrentDomain.BaseDirectory`
(каталога EXE IDE), а не текущего рабочего каталога: одинаково для `bin`,
запуска из Visual Studio и перенесённого комплекта/дистрибутива.
Если локальный INI остался от раннего прототипа, замените в нём только эту строку.
Явный абсолютный путь к другому runtime также поддерживается.
DLL контроллера изолирована от старой IDE и запускается через `dotnet`.
`DotnetPath` позволяет указать другой путь к executable. После изменения
настроек перезапустите IDE. Плагин не сохраняет документ автоматически.

Для unit виртуальное имя файла должно соответствовать имени модуля:
например, `Helpers.pas` для `unit Helpers`. Поиск использует каталог главной
программы и обычные пути компилятора. Диагностика передаётся в стандартный список
IDE с исходным полным именем, строкой и столбцом, чтобы открытый виртуальный
исходник находился так же, как уже сохранённый файл.

Доступ к соседним репозиториям не нужен. Комплект можно переносить вместе с IDE;
выходные каталоги сборки `.codex-build` и `artifacts` для запуска не требуются.
Внешний JSONL-протокол и клиент не меняются: [описание](../../docs/compiler-controller-protocol.md).

## Автоматическая проверка транспорта

### Синхронизация с LanguageServer (промежуточный шаг)

Тот же плагин запускает `PascalABCNet.LanguageServer.dll` из `RuntimeDirectory`.
Второго комплекта компилятора нет, DLL net10 не загружаются в процесс старой IDE.
Controller остаётся JSONL, LanguageServer использует LSP `Content-Length` через stdio.
Подписки на открытие/переименование/закрытие и изменения текста передают все
Pascal-вкладки, включая несохранённые и плавающие. Дисковые исходники не меняются.
Изменения текста объединяются с задержкой 200 мс. Метаданные и другие языки исключены
из фоновой синхронизации исходников.

Временное отдельное поле статуса отображает `LSP: подключение…`, `LSP: N файлов`
или ошибку связи. Оно не подменяет сообщения компиляции; число файлов означает
отправленные документы, а не подтверждённый сервером анализ. В net472 поле скрыто,
запросы и обработчики текста приостановлены; сервер остаётся до закрытия IDE.
Отключение пользовательского флага IntelliSense также приостанавливает синхронизацию.
При следующем включении передаётся актуальный снимок. Сбой сервера отображается;
следующее действие редактора восстанавливает сервер и документы. При закрытии среды
выполняются `shutdown`/`exit` и ограниченное по времени принудительное завершение.

Подключён список членов **после точки**: LSP возвращает данные в штатное окно
подсказок IDE с прежними значками, группировкой, фильтрацией, Enter/Tab и Escape.
Нового окна и второго комплекта DLL компилятора нет. Плагин ссылается на
PascalABCNET.exe только для доступа к UI; эта ссылка не копирует оболочку/зависимости.
Наведение мыши на идентификатор запрашивает `textDocument/hover` через тот же сервер
и показывает описание в штатном окне `TooltipServiceManager`. Используется существующее
событие редактора `ToolTipRequest` с его задержкой; собственного таймера наведения нет.
Перед запросом отправляются актуальные тексты всех открытых модулей, включая несохранённые.
Флаг «Подсказка при наведении мышью» управляет этой функцией отдельно от списка после точки.
Правка текста/зависимого модуля, уход мыши, клавиша, прокрутка, потеря фокуса, Save As,
закрытие и смена платформы отменяют ожидающий ответ и скрывают показанное описание.
Подсказки маркеров ошибок, свёрнутого текста и отладчика имеют приоритет.
В net472 обработчики LSP отсоединены: остаётся исторический hover.
Наведение работает также внутри штатной вкладки метаданных .NET 10. Её текст
передаётся по запросу как отдельный виртуальный документ, не подменяющий исходные
модули и не входящий в счётчик файлов LSP. На диске ничего не создаётся.
Сервер адаптирует только копию для анализа: добавляет разделы unit и убирает
CLR-суффикс `&` у возвращаемого типа; текст вкладки и координаты членов сохраняются.
Проверка: в метаданных `String` наведите мышь на `integer` и свойство `Length`.
Подсказка параметров подключена после `(`, `[`, `,` через `textDocument/signatureHelp`.
Используется штатный `PABCNETInsightWindow`: перегрузки переключаются стрелками,
текущий параметр выделяется жирным по меткам/UTF-16 диапазонам LSP. Вложенные вызовы
используют штатный стек окна: после `)` возвращается внешняя подсказка.
Запятые/скобки в Pascal-строках и комментариях не создают запросов; запятые внутри
массива не переключают параметр внешнего вызова. Типы и перегрузки анализирует сервер,
локально проверяется только область жизни подсказки. Escape, правка зависимости,
Save As, закрытие, потеря фокуса и смена платформы отменяют устаревшие ответы.
Учитывается отдельный флаг «Подсказка параметров функции». Событие изменения текста
наблюдается после обычной вставки символа: дополнительного перехвата клавиш нет.
Ctrl+Space пока **не подключён**.

Ctrl+щелчок левой кнопкой мыши в .NET 10 ищет реализацию через
`textDocument/implementation`, затем определение через `textDocument/definition`.
Используются существующие DOM-методы CodeCompletion и штатный переход IDE, не
второй анализатор. Перед запросом передаются текущие тексты всех открытых вкладок.
Pascal-символ открывает исходный `.pas` (открытая вкладка не перезаписывается);
CLR-символ открывает штатную вкладку с метаданными. Метаданные получаются по
виртуальному URI через `pascalabc/metadata`, без создания файлов на диске.
Правка любого открытого модуля, смена позиции/фокуса, Escape, Save As, закрытие
или смена платформы отменяют старый ответ. Отпускание Ctrl после щелчка не отменяет
переход. В net472 подписки отсоединяются: работает исторический Ctrl+щелчок.

Проверка: откройте программу и подключённый модуль с `procedure p1`; измените
модуль без сохранения, Ctrl+щелчок по вызову `p1` должен открыть текущую реализацию.
Ctrl+щелчок по `Substring` в `s.Substring(1)` должен открыть метаданные `string`.
Повторите переход после Save As и при возврате на .NET 4.7.2.
Сквозной тест: `CompileNet10.Tests.exe --navigation-ui <bin-net10>`.

Ручная проверка параметров: наберите `s.Substring(`, затем `1,` — подсказка должна
показать перегрузки и выделить второй параметр. Стрелки выбирают перегрузку;
`)` и Escape закрывают окно. Проверьте вложенный вызов и возврат на .NET 4.7.2.

Ручная проверка: в режиме .NET 10 наберите `begin var s := 'abc'; s.Substring(1); end.`,
наведите мышь на `s` или `Substring` и дождитесь обычной подсказки. Затем измените
несохранённый тип/имя, проверьте новое описание и возврат на .NET 4.7.2.
Перед запросом completion без ожидания debounce отправляется актуальный текст всех
открытых Pascal-файлов, включая несохранённые модули. Пока сервер отвечает, можно
допечатать префикс имени; остальные правки, перемещение курсора, Escape, Save As,
закрытие вкладки и смена платформы отменяют устаревший ответ. Ошибка LSP не прерывает
редактирование. Настройки «Включен» и «Подсказка по точке» учитываются без перезаписи.
Для ручной проверки переключитесь на .NET 10, откройте/создайте ещё `.pas`:
число файлов должно увеличиться; Save As его не меняет; подтверждённое закрытие
уменьшает, отмена закрытия не меняет. Переход на 4.7.2 скрывает поле и возвращает
старый IntelliSense. При обратном переключении сервер получает текущий текст.
Проверьте Compile/Run/Stop обоих режимов и закрытие IDE без оставшегося LSP-процесса.
Для подсказки в .NET 10 напишите `begin var s := 'abc'; s.` — после точки должен
появиться список с `Substring` и `Length`. Наберите `Sub` и выберите `Substring`
клавишей Tab: должно получиться `s.Substring`, без повторной точки/префикса.
