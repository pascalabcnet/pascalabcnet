# Compile .NET 10: экспериментальный плагин

Отдельный плагин `net472` для существующей IDE. Добавляет пункт меню
плагинов и текстовую кнопку **Compile10**. Через JSON Lines обращается
к долгоживущему контроллеру из текущего PascalABC.NET и компилирует текущий текст редактора.
Запрос выполняется асинхронно; результаты и диагностика идут в сообщения
компилятора. При закрытии IDE плагин завершает свой контроллер.

## Сборка

Из корня основного репозитория:

```powershell
& .\scripts\build-compile-net10-plugin.ps1 -Configuration Debug
```

Предварительно должна быть собрана обычная IDE: проект использует существующий
`bin/PluginsSupport.dll` как контракт и не пересобирает проекты оболочки.
Если плагин уже загружен в IDE, перед пересборкой закройте эту IDE.

Для стандартной панели ввода нужна IDE и `PluginsSupport.dll` из текущих исходников:
`dotnet build VisualPascalABCNET/VisualPascalABCNET.csproj -c Release -p:PABCNET_LEGACY_ONLY=true`.
В старой бинарной оболочке без нового необязательного интерфейса Run10 сообщает
о необходимости пересборки; скрытого перехвата обработчиков и новой панели нет.

Результат — `bin/CompileNet10Plugin.dll` и полный `bin/CompilerHost/net10/`.
Controller и Worker собираются только из проектов текущего репозитория;
их зависимости .NET 10 изолированы от DLL оболочки net472.
Скрипт вызывает `scripts/build-compiler-host.ps1 -Target net10 -IncludeRuntime`.
`Lib` и `Lng` комплектуются версионируемыми файлами текущего `bin` без
старых PCU, DLL, EXE и PDB. Модули компилируются из исходников при необходимости.
Проект не добавляется в `PascalABCNET.sln`; основная сборка и установщик
не меняются и не требуют .NET 10 SDK. Для отдельной сборки host нужен .NET 10 SDK;
для запуска готового комплекта — установленный .NET 10 runtime.

Сборка только плагина (например, из Visual Studio) остаётся обычной:
`dotnet build VisualPlugins/CompileNet10/CompileNet10.csproj -c Debug`.
Она не пересобирает host автоматически. Если его ещё нет, сначала выполните скрипт выше.

## Проверка в IDE

1. Запустить `bin/PascalABCNET.exe` после сборки плагина.
2. Найти кнопку **Compile10** и одноимённый пункт меню плагинов.
3. Открыть или создать `.pas` и нажать кнопку; сохранять изменения не требуется.
   В сообщениях компилятора должен появиться результат или диагностика.
   Ошибки также выводятся в стандартный список IDE: двойной щелчок или Enter
   переводит к указанному файлу, строке и столбцу. Перед новым запросом список
   очищается. Новые вкладки должны иметь назначенное полное имя исходника
   (обычная новая программа IDE уже получает такое имя).
   Оба запроса, Compile и Run, содержат `runtimeModule=__RedirectIOMode` и
   `sourceFiles`: главную программу и открытые изменённые Pascal-исходники.
   Новые открытые `.pas`, ещё не существующие на диске, включаются также при
   отсутствии отметки изменения. Неизменённые сохранённые модули читаются с диска.
   Снимок собирается до отправки запроса, включая скрытые и плавающие вкладки;
   текст не переписывается и исходники на диск не записываются.
   Выходные файлы создаются в `net10-output` рядом с исходником.
   **Run10** сначала компилирует файл и только при успехе запускает
   сборку через `DotnetPath` без внешней консоли. Для запуска запрос содержит
   `runtimeModule=__RedirectIOMode`; программа получает `[REDIRECTIOMODE]` и handshake `GO`.
   Вывод, включая текст без перевода строки и исключения, идёт в окно вывода
   исходной вкладки IDE. Успешный код завершения не печатается.
   По `[READLNSIGNAL]` от `Readln` открывается стандартная панель ввода IDE.
   Enter и кнопка ввода отправляют текст в процесс Run10, после чего панель скрывается.
   Стандартная кнопка остановки на этой панели останавливает Run10;
   кнопка **Stop10** на toolbar доступна также вне ожидания ввода.
   Ожидание и набранный текст привязаны к исходной вкладке обычным механизмом IDE.
   После завершения/остановки Run10 обработчик освобождается. Обычный запуск net472
   использует прежний RunManager без изменения протокола или обработки ввода.
   Рабочий каталог — каталог исходника; аргументы берутся из настроек запуска IDE.
   Запуск выполняется без отладчика и без подключения к старому RunManager.
   Одновременно допускается одна программа .NET 10; обычный запуск IDE
   останавливает экспериментальную программу. Закрытие её вкладки или IDE
   также завершает процесс. Переключение вкладки не перенаправляет вывод.
   В статусной строке отображаются подготовка, компиляция, результат компиляции,
   выполнение, ожидание ввода, остановка и завершение .NET 10. Плагин не получает
   внутренние фазы компилятора: JSON-протокол пока возвращает только итоговый ответ.
   Если обычная IDE обновила статус, позднее сообщение .NET 10 его не перезаписывает.
4. Проверить обычную компиляцию существующей кнопкой IDE.

Чтобы отключить эксперимент, закройте IDE, уберите `CompileNet10Plugin.dll`
из каталога приложения и запустите IDE снова. При использовании другой копии
IDE копируются DLL плагина, исходный INI и весь каталог `CompilerHost/net10`,
без замены её `PluginsSupport.dll` или других DLL оболочки. Можно собрать
комплект непосредственно туда:

```powershell
& .\scripts\build-compile-net10-plugin.ps1 -IdeDirectory 'D:\Other IDE' -Configuration Release
```

Каталог `CompilerHost/net10` — генерируемый: скрипт пересоздаёт только его.
Не храните в нём собственные исходники. Скрипты установщика пока не изменяются.

При первой сборке настройки копируются в `bin/CompileNet10Plugin.ini`;
существующий пользовательский INI не перезаписывается. `RuntimeDirectory` указывает
на полный готовый runtime с `PABCCompilerController.dll`, `ZMQServerPas.dll`,
их `.runtimeconfig.json`/`.deps.json`, DLL зависимостей и стандартными модулями.
По умолчанию: `RuntimeDirectory=CompilerHost\net10`. Такой же локальный путь
используется без INI. Он вычисляется относительно `AppDomain.CurrentDomain.BaseDirectory`
(каталога EXE IDE), а не текущего рабочего каталога: одинаково для `bin`,
запуска из Visual Studio и перенесённого комплекта/дистрибутива.
Если локальный INI остался от раннего прототипа, замените в нём только эту строку.
Явный абсолютный путь к другому runtime также поддерживается.
DLL контроллера изолирована от старой IDE и запускается через `dotnet`.
`DotnetPath` позволяет указать другой путь к executable. После изменения
настроек перезапустите IDE. Плагин не сохраняет документ автоматически.

Для unit виртуальное имя файла должно соответствовать имени модуля:
например, `Helpers.pas` для `unit Helpers`. Поиск использует каталог главной
программы и обычные пути компилятора. Диагностика передаётся в стандартный список
IDE с исходным полным именем, строкой и столбцом, чтобы открытый виртуальный
исходник находился так же, как уже сохранённый файл.

Доступ к соседним репозиториям не нужен. Комплект можно переносить вместе с IDE;
выходные каталоги сборки `.codex-build` и `artifacts` для запуска не требуются.
Внешний JSONL-протокол и клиент не меняются: [описание](../../docs/compiler-controller-protocol.md).

## Автоматическая проверка транспорта

```powershell
dotnet build VisualPlugins/CompileNet10.Tests/CompileNet10.Tests.csproj
dotnet run --project CompilerControllerSmokeTest -c Release -- --runtime .\bin\CompilerHost\net10 --target net10
& .\VisualPlugins\CompileNet10.Tests\bin\Debug\net472\CompileNet10.Tests.exe "$PWD\bin\CompilerHost\net10"
```

Проверяются разбиение служебных сообщений между чтениями потока, реальная
компиляция, `Readln`, кириллица, вывод без перевода строки, исключения и остановка.
Также проверяются выбор файлов снимка, изменённая главная программа и unit,
новые виртуальные файлы, смешанные дисковые модули, повторная компиляция unit,
диагностика unit и отсутствие записи снимка на диск.
Сбор текстов реальных вкладок, переход по двойному щелчку, отрисовку строки ввода,
переключение вкладок и обычный запуск нужно проверить в IDE.
Тесты также проверяют поиск runtime без INI и с INI, относительные/абсолютные
переопределения и независимость от рабочего каталога для трёх вариантов запуска.

Ручная проверка после полного перезапуска IDE: Compile10 и Run10 для
`uses System.Text.Json; begin Println(JsonSerializer.Serialize(42)); end.`;
ожидается `42`. Затем программа с `ReadString`/кириллицей, Stop10 при ожидании
ввода и обычная кнопка запуска net472. Для проверки переносимости скопируйте
комплект в другую папку и запустите IDE оттуда с другим рабочим каталогом.
