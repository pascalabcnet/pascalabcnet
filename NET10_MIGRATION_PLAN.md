# Поддержка PascalABC.NET на .NET Framework и .NET 10

Актуальное состояние на август 2026 года.

Первоначальный план миграции консольного компилятора выполнен. Этот документ теперь фиксирует существующую архитектуру, способы проверки и оставшиеся самостоятельные этапы развития.

## 1. Текущее состояние

Из одного репозитория собираются две линии консольного компилятора:

| Линия | Целевая платформа | Выходной каталог |
|---|---|---|
| Legacy | .NET Framework 4.0 (`net40`) | `bin` |
| Modern | .NET 10 (`net10.0`) | `bin-net10` |

В обеих линиях доступны `pabcnetc` и `pabcnetcclear`, использующие общее ядро компилятора. Основные проекты ядра имеют цели `net40;net10.0`.

Существующая графическая среда VisualPascalABC.NET остаётся на .NET Framework 4.7.1 и использует legacy-ядро. Её перевод на .NET 10 не входит в завершённый этап миграции консольного компилятора.

## 2. Что уже выполнено

- Введена двухцелевая сборка ядра и консольных компиляторов.
- Артефакты `net40` и `net10.0` разведены по каталогам `bin` и `bin-net10`.
- Добавлены символы условной компиляции `PABCNET_LEGACY` и `PABCNET_MODERN`.
- Генератор IL и загрузка сборок адаптированы к .NET 10, включая `System.Private.CoreLib` и современный Reflection.Emit.
- Исправлены обнаруженные различия генерации IL для generic-типов, перечислений, многомерных массивов, делегатов, интерфейсов, `ref`-возвратов и других конструкций.
- Восстановлена работа `decimal` под .NET 10.
- Стандартные модули modern-линии пересобираются собственным компилятором и имеют отдельные PCU.
- Системные сборки .NET 10 разрешаются централизованно: компилятор и IntelliSense используют один кешируемый набор сборок и его зависимости.
- `CodeCompletion` и необходимые frontend-проекты поддерживают `net40;net10.0`.
- Полные консольные тесты локально проходят для обеих платформ; рабочие файлы и результаты платформ разделены.
- Создаётся отдельный ZIP-дистрибутив консольного компилятора .NET 10.

## 3. Архитектурные правила

1. Legacy-поведение и возможность сборки под `net40` сохраняются.
2. Modern-код может использовать API .NET 10 и не обязан ограничиваться API .NET Framework 4.0.
3. Общие алгоритмы остаются едиными. Различия платформ оформляются небольшими ветками `PABCNET_LEGACY`/`PABCNET_MODERN` или отдельными реализациями.
4. Исправления не вносятся в компилятор ради одного конкретного стандартного модуля: сначала выделяется общий минимальный пример.
5. RTL, PCU, исполняемые файлы и результаты тестирования разных платформ не смешиваются.
6. Старый VisualPascalABC.NET не получает зависимостей от LSP, VS Code или внешнего tooling.

## 4. Сборка и проверка

### Legacy-консольный компилятор

```bat
dotnet build pabcnetc.sln -c Debug -p:TargetFramework=net40 -m:1
bin\pabcnetc.exe program.pas
```

### Консольный компилятор .NET 10

```bat
dotnet build pabcnetc.sln -c Debug -p:TargetFramework=net10.0 -m:1
bin-net10\pabcnetc.exe program.pas
```

Пересборка базовых стандартных модулей:

```bat
_RebuildStandartModules_net10.bat Release
```

### Тесты

```bat
_RunConsoleTests_net40.bat
_RunConsoleTests_net10_clean.bat
```

Вариант `net10_clean` создаёт чистое modern-окружение и исключает влияние оставшихся PCU и результатов предыдущих запусков.

### Дистрибутив консольного компилятора .NET 10

```bat
_BuildConsoleNet10Distribution.bat
```

Результат создаётся в `Release\PascalABCNET-Console-net10.zip`.

Legacy-инсталляторы и `_GenerateAllSetups.bat` пока сохраняют прежнюю .NET Framework-схему.

## 5. IntelliSense и внешний tooling

Общий проект `CodeCompletion` уже собирается для `net40` и `net10.0`. Регистрация Pascal и editor-neutral сервисы completion, hover и signature help доступны без зависимости от VisualPascalABC.NET.

Внешний LanguageServices/LSP развивается в отдельном tooling-репозитории, подключающем PascalABC.NET как git submodule. Адаптация LSP, координат редактора, сериализация запросов к существующему глобальному состоянию и VS Code extension относятся к tooling, а не к ядру компилятора.

## 6. Что осталось

1. Добавить в GitHub Actions отдельную сборку и тестирование modern-консоли, не ломая существующую legacy-сборку и создание инсталляторов.
2. Продолжить внешний LanguageServices/LSP и VS Code extension.
3. Определить способ запуска modern-программ через общий хост (`pabcrun`) либо оставить стандартный .NET host.
4. Отдельно решить вопрос перевода графической оболочки и её плагинов на `net10.0-windows`. Это новый этап, а не часть завершённой миграции консольного компилятора.
5. Постепенно добавлять modern-варианты тестов, зависящих от сторонних DLL.

## 7. Критерии сохранения готовности

После изменений в ядре, `NetGenerator`, `NetHelper`, загрузке сборок или IntelliSense необходимо:

- собрать `net40` и `net10.0`;
- прогнать соответствующие регрессионные тесты;
- при существенных изменениях прогнать оба полных консольных набора;
- проверить чистую пересборку standard modules для .NET 10;
- не допускать смешивания артефактов `bin` и `bin-net10`.

## 8. Технический долг: перегрузки с лямбдами

Временная сортировка кандидатов перегрузки для `Task<integer>.Run(()->1)` не должна становиться окончательной семантикой. Разрешение перегрузок должно быть независимо от порядка, в котором Reflection возвращает методы.

Необходимо:

- изолированно проверять каждую перегрузку;
- полностью восстанавливать состояние `function_lambda_definition` после проверки кандидата;
- выполнять окончательную конверсию лямбды только после выбора лучшей перегрузки;
- удалить временную modern-сортировку;
- добавить тесты с одинаковыми перегрузками в разном порядке для `net40` и `net10.0`.
